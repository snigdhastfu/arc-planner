# Decisions and assumptions

Each entry: what was decided and why. Newest at the bottom.

1. **Go toolchain.** Go 1.27.3 was found at `~/.local/go` (not on PATH). SPEC section 2 asks for Go >= 1.24, so it is used as is. `go.mod` says `go 1.24` so CI (`setup-go` with `go-version-file`) and forks can use any toolchain from 1.24 up.
2. **`gh` missing.** The GitHub CLI is not installed on the build machine. Everything else is finished, and the exact publish commands are in README "Publish" and the final report (SPEC section 15).
3. **Fredoka.** Downloaded the variable `Fredoka[wdth,wght].ttf` from google/fonts, then instanced it to static 400/500/600 at width 100 and subset it to Latin + Latin-1 + Latin Extended-A + a few symbols (arrows, middle dot, ellipsis), saved as woff2 (about 15 KB each) with fontTools. OFL.txt is bundled next to the fonts.
4. **Text colour.** The mockups use `#F4F1EA` for body text, but the fixed palette has Platinum `#F0EFEF` and SPEC tokens say `--text:#F0EFEF`. The palette wins. The difference is invisible on black.
5. **Playwright.** `playwright-core` only (no browser download), pointed at the system Chrome. It lives in `tools/e2e/package.json` and is never imported by the app.
6. **Doodle matcher word boundaries.** A "whole word" boundary is any non-letter character, so digits count as boundaries. That is what makes the SPEC case "vitamin d3" score `vitamin d` (sun, 9) above `vitamin` (pill, 7).
7. **Quick-add doodle matching.** "Chem exam" ties `chem` (flask, 4) with `exam` (book, 4), and alphabetical tie-breaking would pick book, but SPEC expects flask. The parser therefore matches on the title with the recognised type word removed ("chem"), falling back to the full title and then to the type default. The standalone matcher still follows SPEC section 8 exactly.
8. **Done minutes are not double counted.** SPEC says finishing a block adds its minutes to `DoneMin` *and* sets the block `done`, while `remaining = EffortMin - DoneMin - done-block minutes`. Taken literally, that counts the same work twice. The planner uses `remaining = EffortMin - max(DoneMin, done-block minutes)`. `planner.BlockAction` (exposed as an extra bridge call, `arc.blockAction`) is the single place that updates both, and it is idempotent, so a double-fired swipe counts once.
9. **`plan()` keeps existing blocks.** Nothing moves silently, so `plan` keeps every existing block that is still valid (done, pinned, skipped, and planned ones that still fit) and places only effort that isn't covered yet. Only `replan` releases planned and skipped work, and its result is always shown as a diff for approval. Editing an item's effort or deadline, changing the profile, or reordering routines does re-place *that* item's or *those* routines' future planned blocks, because the user asked for exactly that change.
10. **Sleeping-in lifecycle.** A skipped work block keeps its effort reserved, so `plan()` does not quietly re-add it, and the day counts as drifted. On replan the skipped block becomes `moved`, and the review shows it as "moved" from its old time to its new home (the mockup's "Stats flashcards: Today 4 pm → Wed 9:30 am"). If the user rejects that change, the block stays skipped and pinned.
11. **Drift.** A day counts as drifted when a non-pinned work block ended before now and is still `planned`, when a skipped work block hasn't been re-homed yet, or when replan adds or worsens an at-risk item. Overrun has no separate signal, because a block left running 20+ minutes past its end shows up as a past planned block. Routines never cause drift: a forgotten 2-minute routine shouldn't nag. Pinned blocks are the user's call and never cause drift either.
12. **Rejected changes.** `applyChanges` starts from the proposal and reverts each rejected change, so the old block comes back pinned. An accepted change that would overlap a reverted block is reverted too and reported in `conflicts`.
13. **Snooze.** The block moves 15 minutes later, or to the next free 5-minute slot that fits later the same day, and is pinned there. If nothing fits, Arc says so kindly and suggests sleeping in instead.
14. **Event blocks.** Fixed events come out as `kind:"event"` blocks, so the arc can show them. All-day events (midnight to midnight, 20 h or longer) don't block the day; otherwise a birthday would wipe out all study time.
15. **Routine recurrence anchor.** `Interval > 1` counts from the item's `Start` day when one is set, otherwise from a fixed Sunday (2000-01-02). Weekly rules count weeks from the Sunday on or before the anchor. `Until` is inclusive.
16. **Horizon default.** `plan` covers max(21 days, days until the latest deadline), capped at 120.
17. **Arc smoothing.** SPEC asks for a ~40-minute smoothstep blend. With the real energy windows that made cliff-like steps, while the mockup (which wins on visuals) shows gentle hills. The arc uses a smoothstep-weighted moving average over ±80 minutes instead, plus a rise out of sleep and back down at the edges. It is still sampled every 10 minutes and drawn Catmull-Rom → Bezier, and nodes are evaluated on the exact same spline.
18. **Arc nodes.** Radius follows `clamp(8 + minutes/6, 8, 24)`, but neighbouring nodes shrink (to a minimum of 9) rather than overlap, matching the uncluttered mockup. Each routine group shows as one node (the next routine's doodle, with a count), not 2-minute specks.
19. **Default energy windows.** Low 07–08, okay 08–09:30, peak 09:30–13:00, okay 13:00–15:00, peak 15:00–18:00, okay 18:00–20:00, low 20:00–23:00. Onboarding asks about five parts of the day and maps them onto windows.
20. **Focus card scope.** It shows work and event blocks. Routines live on the Routines tab and the arc; a 2-minute meds block shouldn't take over the focus card.
21. **Routine tiles.** A tap opens a quick sheet (Done today / Sleep in / Earlier / Later / Edit). Long-press then drag reorders, and the Earlier/Later buttons are the non-drag path.
22. **Settings entry.** The nav has the four mockup slots, so Settings is reached from the logo mark in the top-right of every screen.
23. **Repo link in About.** It's derived from the Pages URL (`<owner>.github.io/<repo>`), so forks link to themselves and no owner or repo is hardcoded. It is hidden elsewhere.
24. **Clock override.** `?now=<ISO>` shifts the app clock, and time keeps ticking from there. It's used by the e2e tests and screenshots, and it's harmless for users.
25. **Service worker reload.** The page reloads on `controllerchange` only after the user taps "A new version is ready". A first install also fires `controllerchange` (via `clients.claim()`) and must not reload.
26. **Offline e2e.** Playwright's `setOffline` blocks requests before they reach a service worker, so the offline check serves `dist/` from a private server and switches it off instead. That is a truer test.
27. **Text colour of labels/curve.** The palette's Platinum `#F0EFEF` is used everywhere the mockup used `#F4F1EA`.
28. **Neutral greys.** Hairlines, tracks and the muted text colour (`#A8A8B0`, from SPEC tokens) are neutral greys, not palette colours. They're only used for outlines and secondary text.
29. **Postcards.** Opening Tuck in auto-saves the day's postcard (SVG) to the archive. "Save postcard" rasterises it to PNG, with Fredoka embedded as base64 so the PNG looks the same, and shares it or downloads it.
30. **Release workflow.** It uses the preinstalled `gh` CLI rather than a third-party action, which means one fewer dependency.
